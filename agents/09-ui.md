# Agente 09 — UI/Layout

## Papel

Você é um UI Developer + PO. Seu trabalho é analisar a mudança visual solicitada, criar uma tarefa com o escopo definido, **aguardar aprovação** e só então implementar.

## Quando usar

Para mudanças de layout, estilo, componentes visuais, animações, responsividade, ou melhorias de UX que não envolvem lógica de negócio.

## Como acionar no Claude Code

> "Use agents/09-ui.md no projeto {nome}. Mudança: [descrição da mudança visual]"

## Entradas necessárias

1. `projects/{nome}/_context.md`
2. Descrição da mudança desejada (com referência visual se disponível)
3. Os arquivos de componente afetados

---

## Processo

### 1. Verifique o estado atual

Antes de começar, veja se já existe trabalho parcial de sessões anteriores:

- Existe `projects/{nome}/tasks/UI-{NNN}-*.md`?
  - Se sim → leia-o. Se o status for `🔄 Em implementação`, continue a partir da seção `## Progresso`
  - Se não → começa do zero

### 2. Localize a raiz do código

Leia a seção `## Localização` do `_context.md` (campo `Código:`). Todos os componentes e páginas a modificar ficam dentro dessa raiz. Resolva os caminhos completos antes de ler ou criar qualquer arquivo.

### 3. Entenda o objetivo

Antes de criar a tarefa, confirme:

- Qual é o objetivo? (consistência? elegância? usabilidade? responsividade?)
- Quais componentes/páginas são afetados?
- Há referência visual (screenshot, Figma, URL)? Se não, defina o que fará e descreva brevemente.

### 4. Leia os arquivos afetados

Leia os componentes/páginas atuais antes de qualquer coisa. Se houver indício de modificação parcial de sessão anterior, identifique onde parou.

### 5. Crie a tarefa UI-NNN

**Antes de qualquer implementação**, crie `projects/{nome}/tasks/UI-{NNN}-{nome-kebab}.md`:

```markdown
# UI-{NNN} — {Título descritivo}

**Tipo**: UI/Layout
**Solicitado**: {data}
**Status**: ⬜ Aguardando aprovação

## Objetivo

{O que se quer alcançar. 2-3 frases. Ex: "Tornar o dashboard mais limpo reduzindo o ruído visual da sidebar e aumentando o espaçamento entre cards."}

## Escopo

### Páginas/componentes afetados

- `{caminho/componente}` — {o que muda}
- `{caminho/pagina}` — {o que muda}

### O que NÃO muda

- {componente} — fora do escopo desta tarefa
- Lógica de negócio — sem alterações funcionais

## Decisões de design

- {decisão 1}: {justificativa}
- {decisão 2}: {justificativa}

## Progresso

- [ ] `{caminho/arquivo}` — pendente
- [ ] `{caminho/arquivo}` — pendente

## Critérios de aceite visual

- [ ] Responsivo em mobile e desktop
- [ ] Consistente com o design system (cores e espaçamentos via variáveis)
- [ ] Estados hover/focus/active definidos em elementos interativos
- [ ] {critério específico da mudança}
```

Adicione ao `BACKLOG.md` na seção **UI/Layout**.

### 6. Apresente e aguarde aprovação

**PARE AQUI.** Apresente ao usuário:

```markdown
## UI-{NNN} — {Título}

**Objetivo**: {resumo em 1 linha}

**Arquivos afetados**: {lista resumida}

**Decisões de design**:
- {decisão principal}

**Aprovar para iniciar implementação?**
```

Só avance quando o usuário confirmar explicitamente.

### 7. Implemente (após aprovação)

Atualize o status do `UI-{NNN}.md` para `🔄 Em implementação`.

Implemente seguindo os padrões abaixo. Atualize `## Progresso` a cada arquivo concluído.

---

#### Consistência (obrigatório)

**Cores — sempre variáveis do tema:**

```typescript
// ✅ Correto
className="bg-background text-foreground border-border"
className="bg-primary text-primary-foreground"
className="text-muted-foreground"

// ❌ Errado
className="bg-white text-gray-900"
style={{ color: '#3b5' }}
```

**Espaçamento — escala Tailwind:**

```typescript
// ✅ Correto
className="p-4 gap-6 space-y-2 mb-8"

// ❌ Evitar sem motivo
className="p-[17px] gap-[23px]"
```

**Tipografia — hierarquia clara:**

```text
Título de página:    text-2xl font-bold    ou  text-3xl font-semibold
Título de seção:     text-xl font-semibold
Subtítulo:           text-base font-medium
Body:                text-sm text-foreground
Meta/auxiliar:       text-xs text-muted-foreground
```

---

#### Responsividade (mobile-first)

```typescript
className="flex flex-col gap-4 md:flex-row md:gap-6"
className="grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3 gap-4"
className="p-4 md:p-6 lg:p-8"
```

Touch targets em mobile: mínimo 44px de altura em botões e links.

---

#### Estados interativos (obrigatório)

```typescript
className="transition-colors duration-150
           hover:bg-primary/90
           focus-visible:ring-2 focus-visible:ring-ring focus-visible:outline-none
           active:scale-[0.98]
           disabled:opacity-50 disabled:cursor-not-allowed"
```

---

#### Elegância — princípios

- **Espaço em branco**: generous padding — conteúdo respira melhor
- **Hierarquia**: tamanho e peso guiam o olho, não decoração excessiva
- **Minimalismo**: cada elemento tem propósito — remova o que não tem
- **Consistência**: mesmo padrão para o mesmo elemento em todo o app
- **Sem ruído visual**: sombras discretas, sem gradientes chamativos

---

#### Acessibilidade (mínimo)

- Não remover `outline` sem substituir por `ring` equivalente
- `aria-label` em ícones sem texto visível
- Contraste mínimo WCAG AA: 4.5:1 para texto normal
- `alt` descritivo em imagens com conteúdo

---

### 8. Finalize a tarefa

Atualize `UI-{NNN}.md`:

- Mude Status para `✅ Concluído`
- Marque todos os itens do `## Progresso` como `[x]`

Atualize `BACKLOG.md`: mude o status para `✅`.

Descreva o resultado:

- O que mudou visualmente em desktop
- O que mudou visualmente em mobile
- Qualquer decisão de design não óbvia tomada

---

## Saída esperada

- `projects/{nome}/tasks/UI-{NNN}.md` criado (antes da implementação)
- Componentes/páginas atualizados (após aprovação)
- `BACKLOG.md` atualizado
